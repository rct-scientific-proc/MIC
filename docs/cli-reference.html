Section 0

Core concepts the flags refer to

Genuineness score and operating threshold. The model is a K-class softmax classifier whose last class is always hard_negative. Every decision hangs off a single per-sample score:

s = P(not hard_negative) = 1 − softmax(logits)[hard_negative] accept as genuine ⇔ s ≥ threshold class of an accepted sample = argmax over the non-HN classes

The threshold is not trained. After every epoch, the validation split is swept and the largest threshold whose aggregated recall still meets --target-recall is chosen — recall is monotone in the threshold, so the largest passing value is the one with maximum hard-negative specificity. That number is saved inside every checkpoint and reused verbatim by evaluate.py. A checkpoint without its threshold is half a model.

Two refinements on the basic sweep: --min-threshold sets a floor the operating point never crosses (if the target is only reachable beneath it, the epoch operates at the floor with target_met=0); and --threshold-mode per-class gives each genuine class its own threshold, applied by predicted class — easy classes keep high, specific thresholds while hard classes get exactly the slack they need, instead of one global threshold being dragged down to the weakest class's operating point.

Aggregated recall (genuine classes). A genuine sample counts as recalled only if it is accepted (s ≥ t) and classified as its true class. Per-class recalls over the genuine classes present in the split are then combined by --recall-agg:

macro mean(r₁ … r_C) (1,1,1,1,0.1) → 0.82 harmonic C / Σ(1/r_c) — 0 if any r=0 (1,1,1,1,0.1) → 0.36 min worst single class (1,1,1,1,0.1) → 0.10

The arithmetic mean can hide one collapsed class behind several perfect ones; the harmonic mean (the default) is dominated by the worst classes, so a recall target forces every class to perform. Each per-class recall is monotone in the threshold, and so is every aggregate — the sweep logic is identical for all three.

Hard-negative specificity. The fraction of hard negatives rejected (s < t) at the operating threshold. This is the number the pipeline is ultimately trying to maximize, subject to the recall constraint.

Checkpoint selection key. "Best" is ranked by the tuple:

( target met?, specificity at threshold, macro recall )

Meeting the recall target dominates everything; among target-meeting epochs, higher specificity wins; while the target is still out of reach, macro recall is the tie-breaker so early progress is still captured.

Section 1

train.py

python train.py DATA.h5 [options] — trains, validates, logs, checkpoints. Writes last.pt, best.pt, and metrics.csv into the output directory.

Positional & output

h5positional · pathrequired

The dataset file in the h5_format.md layout. On startup the file is validated: all arrays share the first axis, image shape is (N, H, W, C) with C ∈ {1, 3}, the last class is hard_negative, split values are {0, 1, 2}, and the gt flag is checked for consistency with labels == hard_negative. Any violation aborts before training starts. Training reads split 0, validation split 1; split 2 is never touched by this script.

--configpath (.json)default: none

A JSON file of options — keys are the long option names (dashes or underscores both accepted, leading dashes allowed; keys starting with _ are ignored as comments, the same dialect as --optuna-space), including the dataset path as "h5". Precedence, highest first: explicit CLI flags > config file > --smart level presets > built-in defaults — so a config captures an experiment while any flag on the command line still overrides it for one-off variations. Values are type-coerced and validated against each option's choices; unknown keys are an error, and "inf" works for the infinite ratio.

{ "h5": "data.h5", "smart": 4, "target-recall": 0.97, "threshold-mode": "per-class", "imbalance-ratio": "inf", "augment": ["rotation", "gaussianblur"], "amp": true }

Every run also writes its resolved options (CLI + config + presets applied) to <out-dir>/config.json, which is itself a valid --config file — any past run can be reproduced or branched with python train.py --config runs/exp1/config.json --out-dir runs/exp2.

--out-dirpathdefault: runs/<timestamp>

Where checkpoints and metrics.csv land. Reusing a directory appends to its existing metrics.csv — intended for --resume into the same directory; for a fresh experiment give a fresh directory.

Model group

--archresnet18 | resnet34 | resnet50default: resnet18

Backbone size. All three take the same 3×224×224 input and get a fresh K-class linear head. resnet18/34 (11.7M / 21.8M params) are usually enough for snippet-scale imagery and train markedly faster; resnet50 (25.6M, bottleneck blocks) buys capacity when classes differ in fine texture rather than gross shape. The architecture is recorded in the checkpoint, so evaluate.py rebuilds the right one automatically.

--no-pretrainedswitchdefault: off (pretrained)

Train from random initialization instead of ImageNet weights. Default behavior (flag absent) loads ImageNet weights from --weights-path if given, else from torchvision's cache (TORCH_HOME), downloading when online.

Gotcha From random init with few batches per epoch, BatchNorm running statistics lag the batch statistics: for the first ~10–15 epochs validation metrics can look collapsed (recall stuck at chance) while train loss is near zero. It self-recovers. Pretrained weights start from sane ImageNet BN stats and largely avoid the transient — one more reason they are the default.
--weights-pathpath (.pth)default: none

Load ImageNet weights from an explicit file instead of the network/cache — the offline-machine workflow. Produce the file with download_weights.py on a connected box and copy it over. The state dict is loaded into the stock 1000-class model, then the head is replaced, so the file must be the unmodified torchvision ImageNet checkpoint for the chosen --arch (they are not interchangeable across arches). Takes precedence over the cache; ignored if --no-pretrained is set.

Training group

--epochsintdefault: 50

Upper bound on epochs; early stopping (--patience) usually ends the run first. With --resume this is the absolute epoch count, not additional epochs — resuming an 8-epoch run with --epochs 10 trains epochs 8 and 9.

--batch-sizeintdefault: 64

Used for both training and validation loaders. Images are 3×224×224 floats after the input pipeline, so memory scales as ~0.6 MB per sample before activations; drop this first if CUDA runs out of memory, or raise it with --amp on. Batch size also sets how many samples share one BatchNorm statistic — very small values (<16) make BN noisy on top of the class-mix noise inherent to imbalanced sampling.

--lrfloatdefault: 3e-4

AdamW learning rate, constant for the whole run (no scheduler). 3e-4 is a solid fine-tuning rate for pretrained backbones; from-scratch training (--no-pretrained) sometimes wants 1e-3. If the ramp is enabled and metrics oscillate when hard-negative pressure steps up, lowering the LR is the first knob to reach for.

--weight-decayfloatdefault: 1e-4

Weight decay — L2-style shrinkage applied directly to weights (AdamW's decoupled form, or SGD's weight_decay). Mild regularization; raise toward 1e-2 if the genuine classes are tiny and the model overfits them, lower it if underfitting a large dataset. On heavily imbalanced data this knob deserves extra attention: rare-class classifier weights are updated rarely but decayed constantly, biasing logits toward frequent classes — if a rare class stalls, try lowering decay (1e-4 → 1e-5) before reaching for bigger machinery.

--optimizeradamw | sgddefault: adamw

adamw (decoupled weight decay, Loshchilov & Hutter) is the default: forgiving of the LR choice, comfortable with the spiky gradients focal loss and rare classes produce, and the usual pick for fine-tuning pretrained backbones. sgd (momentum, nesterov) is the classic from-scratch CNN choice — capable of a slightly better final model when its LR schedule is well tuned, but far more LR-sensitive; it typically wants roughly a 10x higher --lr than adamw's 3e-4 default. The choice is stored in checkpoints, and --resume refuses a mismatched optimizer (its state cannot carry over); smart-mode rewinds rebuild whichever optimizer is selected.

--momentumfloatdefault: 0.9

SGD only: momentum coefficient (nesterov is enabled whenever it is > 0; 0 gives plain SGD). Ignored by adamw.

--seedintdefault: 0

Seeds Python, NumPy, and torch RNGs, and parameterizes the sampler: the epoch-e draw uses generator seed seed·100003 + e, so a given (seed, epoch) pair always selects and shuffles the same hard negatives — which is what makes --resume line up with the original schedule. cuDNN autotuning is left on, so GPU runs are reproducible in structure but not bit-exact.

--devicecuda | cpudefault: auto

Auto picks CUDA when available. Forcing cpu is occasionally useful to rule out GPU nondeterminism or to train while the GPU is busy. --amp is silently inert on CPU.

--workersintdefault: 0

DataLoader worker processes. The dataset opens its h5 handle lazily inside each worker (never pickling an open handle), so multiprocess loading is safe on Windows' spawn start method. Economics: each worker re-spawns per epoch on Windows, costing a few seconds — for small datasets 0 is genuinely faster; for datasets where decode/resize dominates, 2–8 workers keep the GPU fed. Rule of thumb: raise it only when GPU utilization is low and epoch time is dominated by loading.

--ampswitchdefault: off

Mixed-precision training (CUDA only): forward/loss under autocast in fp16/bf16 with a gradient scaler guarding against underflow. Typically 1.5–2× faster and ~40% less memory on resnet50-class models with no accuracy cost. Validation always computes probabilities in fp32 after the logits, so threshold sweeps are unaffected. The scaler state is checkpointed and restored on resume.

--patienceintdefault: 10 · 0 = off

Early stopping: end the run after N consecutive epochs without improving the selection key (target met, specificity, macro recall) — see Core concepts. Because the key is exactly the training objective, "no improvement" means no better operating point, not merely no lower loss. Set 0 to always run the full --epochs.

Interaction With --ramp-epochs, specificity often dips right after each pressure step and recovers a few epochs later. Give patience enough headroom to ride the ramp out — patience < ramp recovery time can stop the run mid-ramp.
--no-progressswitchdefault: off (bars shown)

Disables the per-batch tqdm progress bars (one per training epoch with a live running-loss readout, one per validation pass). The bars are transient — they clear on completion so the per-epoch summary lines remain the persistent console record. Pass this flag when redirecting output to a log file or running under a scheduler, where carriage-return animation turns into noise.

--resumepath (.pt or run dir)default: none

Continue from a checkpoint — an explicit .pt file, or a run directory (resolves its newest last_* checkpoint). Restores model weights, optimizer state, AMP scaler, the epoch counter, the best-so-far selection key, the hard-negative miner's error scores, and ramp progress — the run picks up as if uninterrupted. Point --out-dir at the same directory to keep one continuous metrics.csv. Hyperparameters are not read back from the checkpoint: pass the same flags again (or deliberately different ones — resuming with a changed LR is allowed).

Objective group

--target-recallfloat 0–1default: 0.95

The recall constraint the validation threshold sweep must satisfy, in the aggregate chosen by --recall-agg. Semantics, precisely: after each epoch, candidate thresholds are every distinct score value in the validation split; the sweep keeps the largest one whose aggregated recall over genuine classes is ≥ this target, then reports hard-negative specificity at that threshold. If no threshold achieves the target, the epoch records target_met = 0 with threshold 0 (accept everything) and the achievable ceiling is logged as max_recall.

  • It does not change the loss — it defines the operating point and the checkpoint ranking.
  • It gates the pressure ramp: ramp progress only advances on epochs where the target was met.
  • Raising it trades specificity away one-for-one along the ROC curve; 0.99 on a 6-class problem is a much harder constraint than 0.95 because every class must clear it on average.
--recall-aggmacro | harmonic | mindefault: harmonic

How per-class recalls combine into the single number the target, the sweep, checkpoint selection, and the ramp gate all use (see Core concepts). Motivating failure case: five genuine classes at recalls (1, 1, 1, 1, 0.1) — macro reports 0.82 and can clear a 0.8 target while the fifth class is nearly dead; harmonic reports 0.36 and correctly fails, forcing the sweep to a threshold (and training toward a model) that serves every class. Guidance:

  • harmonic (default) — punishes weak classes progressively; any class at exactly 0 recall pins the aggregate to 0.
  • macro — the plain average; only appropriate when classes are interchangeable and a weak one is acceptable.
  • min — the strictest reading ("target means every class"); noisy when validation classes are small (one sample flips recall by 1/n).

The chosen aggregate is stored in checkpoints and in the recall_agg CSV column; evaluate.py reuses it so training and evaluation always report the same statistic.

--min-thresholdfloat 0–1default: 0.0

A hard floor no operating threshold may go below — a standing guarantee that any sample scoring under the floor is rejected, regardless of recall pressure. If the recall target is achievable at some threshold ≥ the floor, nothing changes. If it is only achievable beneath the floor, the epoch operates exactly at the floor (previously the failure fallback was threshold 0, i.e. accept everything) and records target_met = 0 with the recall actually achieved there. In per-class mode the floor applies to every per-class threshold.

Interaction The floor makes target_met stricter, and target_met gates both the pressure ramp and best-checkpoint ranking — a floor set too high can hold the ramp at step 0 indefinitely and mark every epoch as below-target. Set it from domain knowledge ("scores under 0.1 are junk"), not as a tuning knob.
--threshold-modeglobal | per-classdefault: global

global: one threshold for every sample (the original behavior). per-class: each genuine class gets its own threshold, and a sample is judged by the threshold of its predicted class. This decomposes cleanly — class-c recall depends only on true-c samples predicted c — so each predicted-class partition is swept independently to its own maximum-specificity threshold at the recall target.

Why it helps: with one global threshold, the hardest class drags the operating point down for everyone (band3 needs t=0.4, so hard negatives resembling the easy classes are also judged at 0.4). Per-class mode lets easy classes keep thresholds near 1.0 while only the hard class gets slack — global specificity is typically strictly better at the same per-class recall.

Semantics changes to be aware of: target_met requires every class (with genuine validation samples) to hit the target — the gate behaves like --recall-agg min even though the reported recall number still uses your chosen aggregate. The global threshold is still computed every epoch as the fallback and logged in the threshold column.

--per-class-min-countintdefault: 20

Per-class mode's small-class guard: a class whose predicted partition in the validation split has fewer than this many samples falls back to the global threshold instead of sweeping its own (a 10-sample partition quantizes threshold choice into useless 0.1 steps). Classes with no genuine validation samples at all always fall back. Fallback classes are flagged in class_thresholds.csv and in the evaluation report. Set 0 to disable the guard entirely.

--imbalance-ratiofloat ≥ 1, inf okdefault: inf

Caps how many hard negatives the model sees per epoch, relative to the genuine population:

hn_budget = min( n_hard_negatives, round(ratio × n_genuine) )

All genuine samples appear every epoch; only the hard negatives are subsampled. 1.0 means a balanced epoch (as many hard negatives as genuine samples); inf (the default) disables the cap and every hard negative is seen every epoch. When the cap binds, which hard negatives are drawn is decided by the miner (below) — so this flag is also the switch that makes mining matter at all: with an infinite ratio the miner has nothing to choose.

--focal-gammafloatdefault: 2.0

The focusing exponent in the focal loss:

FL(p_y) = −alpha[y] · (1 − p_y)^gamma · log(p_y)

γ = 0 recovers plain (alpha-weighted) cross-entropy; γ = 2 (the paper's default) down-weights already-confident samples by (1−p)² so the gradient concentrates on hard, misclassified examples — exactly the regime of a heavily imbalanced set where easy hard-negatives would otherwise drown the signal. Higher γ (3–5) focuses harder but can destabilize early training when everything is misclassified.

--hn-alphafloatdefault: 0.25

The focal alpha weight of the hard_negative class; every genuine class has alpha 1. At 0.25, a hard-negative's loss contribution is quartered: the model is punished lightly for accepting hard negatives and fully for missing genuine samples — the recall-first stance of early training. Raise it toward 1.0 (directly, or via the ramp) to increase the cost of false accepts once recall is established. Values above 1 are legal and flip the emphasis entirely toward specificity.

--class-alphaNAME=VALUE · repeatabledefault: none

Manual focal alpha for a genuine class, e.g. --class-alpha band3=2.0 --class-alpha band1=1.5 — the static escape hatch when you already know which class needs weight (works in any mode, no smart controller required). Genuine classes default to alpha 1; the hard-negative class is controlled by --hn-alpha, not here. Under --rescue, the effective alpha is max(manual, rescue boost).

--class-alpha-autoBETA · optional valuedefault: off · bare flag = 0.999

Derive the genuine classes' focal alphas from their training-split counts using the effective number of samples (Cui et al., CVPR 2019) instead of hand-tuning: each class gets weight (1 − β) / (1 − βn), normalized to mean 1 so the overall loss scale matches the all-ones default. The idea: the value of each additional sample diminishes as a class grows (new samples increasingly overlap what the model already learned), so the "effective" count saturates — rare classes get proportionally more weight, but less aggressively than raw inverse frequency, which over-corrects. β sets where saturation kicks in: 0 is uniform (no correction), 0.99 mild, 0.999 (the bare-flag default) moderate, and values approaching 1 converge to inverse-frequency weighting. The computed alphas are printed at startup and logged per epoch in class_thresholds.csv.

Composition: --class-alpha NAME=VALUE still overrides single classes (manual beats auto), rescue boosts stack on top as max(alpha, boost), and the hard-negative class stays governed by --hn-alpha and the pressure ramp. β is a good --optuna-space dimension (float, 0–0.9999) when you'd rather search it than pick it. Classes absent from the training split keep the default alpha of 1.

Hard-negative pressure ramp

One coordinated schedule for "start recall-focused, then turn up the pressure". Both endpoints interpolate linearly over --ramp-epochs steps, and progress advances only on epochs whose validation met the recall target — the ramp holds position whenever recall slips below target, so pressure never outruns the constraint.

--ramp-epochsintdefault: 0 (no ramp)

Number of ramp steps between the start and end values. 0 disables the schedule: --hn-alpha and --imbalance-ratio apply as-is from epoch 0 (end-values, with no interpolation). Note the unit is successful epochs, not epochs: a run that meets the target every epoch finishes the ramp in exactly this many epochs; a struggling run takes longer. Ramp position is checkpointed and restored by --resume.

--hn-alpha-endfloatdefault: = --hn-alpha

The hard-negative alpha at full ramp. At progress step k of N:

alpha(k) = hn_alpha + (k / N) · (hn_alpha_end − hn_alpha)

Typical use: --hn-alpha 0.1 --hn-alpha-end 1.0 — nearly ignore hard negatives until recall is secured, then weight them as full citizens. Leaving it unset keeps alpha constant while the ratio still ramps.

--imbalance-ratio-startfloat ≥ 1default: = --imbalance-ratio

The imbalance ratio at ramp step 0, interpolating toward --imbalance-ratio at full ramp. Set it low (e.g. 1.0) to begin with balanced epochs and let hard-negative volume grow only as recall holds. An infinite endpoint is handled in budget space: inf is treated as "the ratio that admits every hard negative", so the per-epoch hard-negative count still grows smoothly instead of jumping to everything at the final step.

--recall-firstlevel 1–5 · optional valuedefault: off · bare flag = 3

One-knob preset for how hard training initially chases the recall target before hard-negative pressure (specificity) is allowed to matter — the leveled counterpart to hand-tuning the ramp flags. Level 1 is a brief soft-start (ramp 3, alpha 0.15 → 0.25); level 3 starts nearly hard-negative-free (ramp 12, alpha 0.05 → 0.25, ratio from 1.0); level 5 is a long recall-only opening (ramp 35, alpha 0.01 → 0.25) that earns its pressure slowly. Presets --hn-alpha (the start), --hn-alpha-end, --imbalance-ratio-start, and — in fixed-ramp mode — --ramp-epochs; any flag passed explicitly (or set in --config) overrides its preset entry. Because ramp progress only advances on epochs that meet the recall target, higher levels also mean pressure is earned, not scheduled. Combines with --smart: there the controller paces pressure itself at cycle troughs, so only the endpoint values apply.

Smart mode (adaptive controller)

An adaptive alternative to the fixed ramp (mutually exclusive with --ramp-epochs). Training is structured as LR cycles: within a cycle the learning rate follows a half-cosine from --lr down to --lr-min, and control decisions happen only at the trough, where the model is settled and evaluable. A pressure level p ∈ [0, 1] maps through the same endpoint flags as the ramp (--hn-alpha → --hn-alpha-end, --imbalance-ratio-start → --imbalance-ratio). At each boundary, the cycle's best validation epoch decides:

raise target met, matched/beat last milestone -> cycle best becomes milestone.pt, pressure += step, next cycle restarts at lr_max hold target met but regressed vs milestone -> retry at same pressure rewind target never met -> reload milestone weights + FRESH optimizer, step /= 2, retry from stable pressure + smaller step ceiling > --max-rewinds failures at one level -> accept the stable pressure as this run's ceiling and keep training there

Rewinds restore the last stable-at-pressure checkpoint, not the overall best (which may predate the current pressure level); the optimizer is rebuilt because stale Adam moments would re-poison the restored weights; miner scores survive, so the retry knows which hard negatives caused trouble. The run also keeps a snapshots/ archive of the top-K cycle-best checkpoints, each carrying its own thresholds. In smart mode --patience counts cycles without overall improvement, not epochs (deliberate post-raise dips would trip epoch-level patience).

--smart [1-5]effort leveldefault: off · bare = level 3

Enable the controller at an effort level — how much time the run is allowed to spend reaching the goal. Level 1 trains minimally and aggressively; level 5 is a marathon that creeps toward full hard-negative pressure with tiny steps, deep LR anneals, and many retries. Each level presets the parameters below; any flag you pass explicitly overrides its preset, and the resolved configuration is printed at startup and stored in the checkpoint config.

Level 5's shape is deliberate: 10 successful cycles to reach full pressure, six bisection retries per level before accepting a ceiling, and heavy rescue smoothing — the configuration for "reach the goal slowly over a long time". Pressure always starts at 0 (gentlest settings); the first cycle that meets the recall target creates the first milestone and begins raising. Pressure endpoints (--imbalance-ratio, --hn-alpha-end, …) stay yours — they are data-dependent and no level touches them.

--lr-cycle-epochsintdefault: per level

Epochs per LR cycle. Shorter cycles react faster but judge each pressure level on less evidence; longer cycles are steadier but slower to adapt. The decision cadence and the snapshot cadence are both tied to this.

--lr-minfloatdefault: per level

Trough learning rate. The half-cosine reaches it on the cycle's last epoch — the epoch whose settled state the boundary decision judges.

--pressure-stepfloatdefault: per level

Initial pressure increment per successful cycle (at 0.25, four clean cycles reach full pressure). Each rewind halves the working step, so failed raises turn into a bisection search for the highest sustainable pressure.

--max-rewindsintdefault: per level

Failures tolerated at one pressure level before the controller stops pushing: pressure returns to the last stable level and stays there (ceiling event). The run continues — the best checkpoint still improves — matching the pipeline's always-produce-an-honest-model philosophy.

--keep-top-kintdefault: per level

Size of the snapshots/ archive: the K best cycle checkpoints of the run by selection key, for later comparison or ensembling. Worst is evicted (and its file deleted) when a better cycle finishes.

--rescueswitch · smart mode onlydefault: on at levels 3+

Class rescue: at each cycle trough, per-class validation recalls are EMA-smoothed and any genuine class lagging the recall target by more than a small deadband (2% of the target) gets two boosts for the next cycle, both scaled by its deficit:

deficit_c = (target − ema_recall_c) / target (clamped to [0, 1]) alpha_c = 1 + (rescue_alpha_max − 1) · deficit_c (loss weight) repeat_c = 1 + round((oversample_max − 1)·deficit_c) (epoch copies)

Boosts are recomputed statelessly at every trough, so a recovered class sheds them automatically — no see-saw bookkeeping. Two safety rules: a cycle trained under active rescue never counts as stable enough for a pressure raise (pressure and rescue never change in the same step), and the hard-negative budget stays keyed to the unique genuine count, so oversampling never inflates hard-negative volume. Boost history is logged per class per epoch in the alpha/repeat columns of class_thresholds.csv, boundary events are annotated (hold rescue:band3), and the evaluation report flags classes still under rescue when training ended — the honest signal that reweighting has hit its limit and the class likely needs more data.

--rescue-alpha-maxfloatdefault: 3.0

Focal alpha a rescued class approaches at full deficit (recall 0). A class at half the target gets roughly the midpoint. Combines with manual --class-alpha values as max(manual, boost).

--rescue-oversample-maxintdefault: 3

Repeat factor a rescued class approaches at full deficit: its samples appear up to this many times per epoch. Duplication, not augmentation — more exposure, same information.

--rescue-emafloat 0–1default: per level

Smoothing of per-class recall across troughs (ema = e·prev + (1−e)·now). With ~10 validation samples per class, one trough reading moves in 0.1 steps; smoothing keeps rescue from reacting to that noise. 0 reacts to the latest trough only.

Hard-negative mining

When the imbalance cap forces subsampling, mining decides which hard negatives fill the budget. Each hard negative carries an EMA of its focal loss (score ← 0.7·score + 0.3·loss, first observation taken directly); unseen samples start at a high sentinel score so everything gets tried before anything is written off. High-score (poorly handled) hard negatives are drawn preferentially via weighted sampling without replacement. Scores persist in checkpoints.

--no-miningswitchdefault: off (mining on)

Disable error-driven selection; the budget is filled uniformly at random each epoch. Useful as an ablation baseline, or when hard-negative losses are so uniform that mining adds nothing. Irrelevant when --imbalance-ratio inf (nothing is subsampled).

--mining-random-fracfloat 0–1default: 0.2

The exploration knob: this share of the hard-negative budget is drawn uniformly from the not-yet-mined remainder, the rest by error score. Without it, a hard negative scored low early (perhaps under a stale model) might never be revisited even though the current model would now fail on it — scores only update when a sample is actually seen. 0 is pure exploitation (risk of stale scores), 1 is equivalent to --no-mining. 0.2 keeps roughly one in five slots refreshing the score pool every epoch.

Optuna search (optional)

Hyper-parameter search built into the training CLI, needing only pip install optuna. --optuna N turns one invocation into a study of N trials: each trial re-parses your base command line plus its sampled flags — so presets, --config, and the usual precedence apply. Per trial the hierarchy is explicit CLI flags > sampled space > config file > presets > defaults, and it holds for every value type: sampled values are applied as parse-time overrides rather than command-line tokens, so a sampled false genuinely turns a config-enabled switch off. An option you pass explicitly on the study command line (say --amp --batch-size 96) is pinned for every trial — colliding dimensions are dropped with a single printed note — and each trial records its effective post-parse values (config and presets resolved), which is what trials.csv and best_trial.json report, so recorded parameters always match what actually ran. A sampled combination the parser rejects (e.g. ramp-epochs under --smart) marks that one trial FAILED and the study continues. Each trial trains into <out-dir>/trial_NNN (no per-trial PDF). The study maximizes hard-negative specificity at the recall target: a trial that meets the target scores its specificity; one that doesn't scores recall − 1 (always negative), so unmet trials rank beneath every met one, ordered by how close they came. Each epoch's value is reported to a median pruner, which stops trials that trail the median of earlier trials at the same epoch (after 5 startup trials and the warmup). Outputs: trials.csv (every trial's state, value, parameters, best epoch, recall/specificity, directory), best_trial.json, and the best trial's own config.json, which reproduces it with python train.py --config <that file>. A sensible pattern: search at --smart 1 or a modest fixed epoch budget, then retrain the winning config at full effort. Trials reuse --seed, so configurations are compared under the same data order.

--optunaint · N_TRIALSdefault: off

Run a study of this many trials instead of a single training run. Mutually exclusive with --resume (trials start fresh; an interrupted study resumes through its storage — rerun the same command with the same out-dir and recorded trials are kept).

--optuna-spacepath (.json)default: built-in space

JSON object of {option: spec} where option is any train.py option name (dashes or underscores, leading dashes allowed — the same key dialect as --config; keys starting with _ are comments in both files, with a note printed if a comment key carries what looks like a real spec) and spec is {"type": "float"|"int"|"categorical", "low", "high", "log", "step", "choices"}; a null choice leaves the option at its config/preset value. The whole space is validated before the study or its storage exist: option names (reported in your spelling), duplicate spellings that collapse to one option, spec shapes (types, low/high, non-empty choices, categorical choices checked against the option's own choices), and reserved options the study manages per trial (h5, config, out-dir, no-report, resume, the optuna flags). Dimensions colliding with an explicit CLI flag are removed with a printed note (the flag pins its value — pinning every dimension away errors out). The built-in space searches lr (log 1e-5..1e-2), weight-decay (log 1e-6..1e-2), optimizer, focal-gamma (0.5..4), hn-alpha-end (0.1..1) and recall-first (off or 1–5); example_optuna_space.json in the repo root mirrors it as a starting point. Keep --smart and --ramp-epochs out of the same space — the parser rejects that combination, and a parse error inside a trial aborts the whole study (loudly, so a bad space never burns trials silently).

--optuna-storageURLdefault: sqlite in out-dir

Optuna storage URL. The default sqlite:///<out-dir>/optuna.db makes the study resumable and inspectable with Optuna's own tooling (e.g. optuna-dashboard); point it at a shared database to run trials from several machines.

--optuna-prune-warmupint · epochsdefault: 3

Epochs a trial always runs before the median pruner may stop it. Raise it under --smart, whose rewinds make early epochs non-monotonic — a cycle length or two is a safe value.

--optuna-no-pruneswitchdefault: off (pruning on)

Run every trial to completion. Costs more but gives the sampler clean final values for every configuration, which helps small studies.

Report group

Every run ends with a PDF report (report_<UTCstamp>.pdf in the output directory — timestamped filenames, so reports accumulate as history rather than overwriting): run identity and reconstructed command, a verdict box (including specificity at 95% acceptance recall), an auto-generated warnings section (classes still under rescue, unreachable targets, pressure ceilings, floor binding, fallback classes, high ECE — each with its recommended action), dataset and configuration tables, the training history and controller-timeline charts, a fresh inference pass at the stored operating point (per-class table, genuine-vs-HN ROC, calibration), the operating-point pages the inference report introduced — a score-separation histogram (genuine vs hard_negative samples, log scale) with the stored threshold and fixed-recall thresholds marked, a specificity-at-85/90/95/98%-recall table, a per-class one-vs-rest ROC page, and confusion matrices at candidate operating points (a full-width matrix at the stored threshold, then the same matrix at each fixed-recall threshold; datasets over 15 classes keep the compact heatmap instead) — and one thumbnail page per genuine class: its best predictions (highest-confidence correct), its worst (missed/misclassified first, lowest scores), and its impostors — samples of other labels the model routes to this class, with the ones crossing its threshold flagged ACCEPTED. A final page shows the miner's persistently-hard training negatives. With more than 12 classes, pages cover the worst-recall 12 and the omission is stated. Regenerate for any past run with python report.py <run_dir> <data.h5>.

--no-reportswitchdefault: off (report generated)

Skip report generation. A report failure never fails a finished training run either way — checkpoints and CSVs are already on disk before the report starts.

--report-testswitchdefault: off (validation split)

Use the TEST split for the report's inference pass. Off by default on purpose: an auto-generated report showing test metrics on every training run quietly turns the test split into a second validation set as you iterate. Opt in for final runs.

--report-thumbsintdefault: 16

Thumbnail budget for the sample grids. Per class page: the best- predictions row shows up to min(6, thumbs), the worst and impostor grids up to min(12, thumbs) each; the miner grid uses the full value. Raw dataset images, captioned with predicted/true class, genuineness score, and MISSED/ACCEPTED flags.

Data group

--imagenet-normswitchdefault: off

Input pipeline, always: uint8 HWC → CHW tensor → bilinear resize to 224×224 (antialiased) → scale to [0,1]; grayscale is repeated to 3 channels. With this flag, ImageNet channel statistics (mean 0.485/0.456/0.406, std 0.229/0.224/0.225) are additionally applied — matching what the pretrained backbone saw during ImageNet training, which can help transfer. Off by default per project convention (plain [0,1] inputs).

The flag is recorded in the checkpoint and evaluate.py replays it automatically — train/eval preprocessing can never silently diverge.
--augmentone or more specsdefault: none

Training-split augmentations, applied in the order given. Validation, evaluation, and blind inference are never augmented. Each spec is a catalog name with optional parameters — rotation:p=0.7,degrees=30 on the CLI (ranges written lo-hi, e.g. sigma=0.1-2.0), or a JSON object in a --config file: {"name": "erasing", "p": 0.5, "scale": [0.02, 0.2]}. Every entry's p is its apply probability (p=1 = always). Unknown names and unknown parameters are hard errors that list the accepted set. Catalog with parameters and their defaults:

geometric rotation (p .5, degrees 15) · perspective (p .3, distortion .3) filtering gaussianblur (p .5, kernel 3, sigma 0.1-1.5) sharpness (p .3, factor 2.0) occlusion erasing (p .3, scale 0.02-0.15, ratio 0.3-3.3, value 0) = Random Erasing / Cutout: random black rectangle photometric colorjitter (p .5, brightness/contrast/saturation .2, hue .05) grayscale (p .2) · invert (p .3) · posterize (p .3, bits 4) solarize (p .3, threshold 128) · autocontrast (p .3) equalize (p .3) policy autoaugment (ImageNet policy, no params) randaugment (num_ops 2, magnitude 9) · trivialaugment

All entries run on the raw snippet before resize, in its storage scale (uint8 files: 0–255; uint16/float16/float32 files arrive as float32 in [0, 1] — solarize's default threshold adapts to the scale, 128 vs 0.5) — except erasing, which runs after resize/normalize so the erased fraction is consistent at model scale (its value=0 is black in the [0,1] pipeline, mean-gray under ImageNet norm). Keep erasing's scale modest: a large erase can delete the very evidence that makes a small snippet its class.

Label preservation An augmentation is only valid if the transformed sample still deserves its label. The photometric ops alter intensity and color — when classes are distinguished by intensity, a jittered/inverted/equalized sample of one class can literally become another class (or a hard negative) while keeping its label. For intensity-coded data, the safer subset is rotation, perspective, gaussianblur, sharpness, and erasing (with modest scale). The policy-based entries (autoaugment/randaugment/trivialaugment) were tuned on natural-image benchmarks and freely apply the photometric ops — treat them as convenient but aggressive, and prefer an explicit list when in doubt.

Interactions: augmentation randomizes per-sample loss, so the hard-negative miner's EMA scores get noisier (the EMA absorbs it, but expect slower score convergence); the chosen list is stored in the checkpoint config and shown in the report's reconstructed command.

--augment-pluginFILE.py · repeatabledefault: none

Ship your own augmentations without touching the pipeline code: point this at a Python file and its entries merge into the built-in catalog before your --augment specs are resolved — they get the identical name:key=value CLI syntax, config-JSON objects, and up-front validation. The flag repeats for several files; names must not collide with the built-ins or with another plugin (a hard error, so a plugin can never silently redefine rotation). example_augment_plugin.py in the repo root is a working, heavily commented template.

Anatomy of a plugin file. Two module-level names, one required:

AUGMENTATIONS required: {name: factory} — same shape as the built-in catalog POST_RESIZE optional: set of names that run AFTER resize/normalize

The factory and its inputs. Each factory is a callable whose keyword arguments (with defaults) are the augmentation's user-settable parameters — that signature IS the interface. Writing "gaussnoise": lambda p=0.5, sigma=10.0: … makes --augment gaussnoise:p=0.8,sigma=12 work immediately, an unknown key like sigm= dies up front listing ['p', 'sigma'], and a range written lo-hi (e.g. scale=0.05-0.2) arrives as the tuple (0.05, 0.2). By convention expose p and wrap the transform in v2.RandomApply (see the _maybe helper in the example) so p=1 means "always apply", like every built-in.

The transform and its input tensor. The factory returns any callable mapping an image tensor to an image tensor — a stock torchvision v2 transform, your own torch.nn.Module, or v2.Lambda. What it receives depends on the stage:

pre-resize (default) CHW crop at source resolution in STORAGE scale: uint8 0–255 for uint8 files; float32 in [0,1] for uint16 / float16 / float32 files (uint16 arrives divided by 65535). 1 channel for grayscale, else 3; return the SAME dtype and layout post-resize (POST_RESIZE) CHW float32, 224x224, scaled to [0,1] — ImageNet-normalized when --imagenet-norm is on; use it when the effect must be consistent at model scale (the built-in erasing lives here)

Guarantees that carry over. Plugin augmentations are training-split only (validation/evaluation/inference stay clean), obey the order given in --augment, and are recorded in the run's config.json together with the plugin path — ship the .py next to the config and python train.py --config … reproduces the run, plugins included. An Optuna study loads each plugin once, not once per trial. The same label-preservation caution as above applies doubly to custom ops: an augmentation is only valid if the transformed snippet still deserves its label.

Minimal complete example (the repo's example_augment_plugin.py adds fuller comments):

import torch from torchvision.transforms import v2 def _maybe(p, t): return t if p >= 1 else v2.RandomApply([t], p=p) class GaussianNoise(torch.nn.Module): def __init__(self, sigma): super().__init__() self.sigma = float(sigma) def forward(self, img): # uint8 in, uint8 out (pre-resize stage) noise = torch.randn_like(img, dtype=torch.float32) * self.sigma return (img.float() + noise).clamp(0, 255).to(img.dtype) AUGMENTATIONS = { "hflip": lambda p=0.5: v2.RandomHorizontalFlip(p=p), "gaussnoise": lambda p=0.5, sigma=10.0: _maybe(p, GaussianNoise(sigma)), "gridmask": lambda p=0.3, scale=(0.02, 0.1), value=0.5: v2.RandomErasing(p=p, scale=scale, value=value), } POST_RESIZE = {"gridmask"} # gridmask acts on the float model-scale tensor

Run it: python train.py data.h5 --augment-plugin example_augment_plugin.py --augment hflip gaussnoise:p=0.8,sigma=12 gridmask:scale=0.05-0.2

Section 2

evaluate.py

python evaluate.py CHECKPOINT.pt DATA.h5 [options] — runs a frozen checkpoint on a split using the checkpoint's stored operating point — the global threshold, or the per-class threshold map plus floor when the checkpoint was trained with --threshold-mode per-class. It never re-tunes the operating point, which is what keeps a test evaluation honest: thresholds were chosen on validation, the test split only ever sees them applied. The report lists each class's recall alongside the threshold it operates at, flagging classes on the global fallback. Its PDF carries the same operating-point pages as the training report (score-separation histogram, specificity at fixed recalls, per-class ROC, confusion at candidate operating points), computed on the evaluated split; sections needing both populations are skipped on a split without genuine or without hard-negative samples.

checkpointpositional · .pt or run dirrequired

A checkpoint file from a training run, or the run directory itself (resolves its newest best_* checkpoint). The checkpoint supplies the architecture, class list, normalization flag, and threshold — you cannot pass a mismatched --arch by accident because there is no such flag here. The class list is cross-checked against the dataset and a mismatch aborts.

h5positional · pathrequired

The dataset to evaluate on — normally the same file used for training, but any file with an identical class list works (e.g. a newly collected test set exported with the same classes).

--split0 | 1 | 2default: 2 (test)

Which split to score: 0 train, 1 validate, 2 test. Evaluating split 1 should closely reproduce the training log's numbers for that epoch (a useful sanity check); split 0 measures memorization more than generalization.

--batch-sizeintdefault: 64

Inference batch size. Pure throughput knob — no gradients are stored, so this can usually be several times the training batch size.

--devicecuda | cpudefault: auto

Same semantics as training. CPU evaluation is fine for moderate test sets.

--workersintdefault: 0

DataLoader workers; same Windows economics as in training. A single pass rarely needs more than 0–2.

--no-progressswitchdefault: off (bar shown)

Disables the inference progress bar; same log-friendliness rationale as the training flag.

--out-dirpathdefault: <ckpt dir>/eval_<split>

Destination for report.txt, confusion.csv / confusion.png, roc_genuine_vs_hn.png (operating point marked), roc_per_class.png, calibration.png, history.png, and a full report_<UTCstamp>.pdf for the evaluated split (--no-report skips it, --report-thumbs sizes its grids; the inference already computed for the evaluation is reused when the evaluated checkpoint is the run's best). With more than 8 genuine classes the per-class ROC keeps the worst-AUC classes and the report lists which were omitted — nothing is dropped silently.

calibration.png is a reliability diagram of the genuineness score: samples are binned by predicted s, and each bin's observed genuine fraction is plotted against its mean prediction — the diagonal is perfect calibration, with the stored threshold marked and per-bin counts below. The report adds the expected calibration error (ECE), the count-weighted mean |observed − predicted|. A well-calibrated score makes the threshold interpretable as a probability; an overconfident one still ranks correctly (fine for ROC/threshold purposes) but its value shouldn't be read as P(genuine).

--history-csvpathdefault: metrics.csv beside the checkpoint

Source for the metric-vs-epoch plot. The default finds the training log automatically when the checkpoint still sits in its run directory; pass this explicitly if the checkpoint was copied elsewhere. Missing file ⇒ the history plot is skipped and noted in the report, everything else still runs.

Section 3

inference.py

python inference.py CHECKPOINT IMAGES... --window-width W --window-height H --stride-x S [options] — blind sliding-window inference over full images. Each image is loaded with Pillow, tiled into sub-windows (row-major traversal), and every window goes through the exact training preprocessing and the checkpoint's stored operating thresholds — a window is a detection when accepted as a genuine class. Outputs: detections.csv (every accepted window), a report_<UTCstamp>.pdf (summary table of all images plus the ground-truth analytics sections when --gt is given — with GT the per-image table moves to the final page so diagnostics come first), and annotated whole-image overlay PNGs in assets/ (raw window boxes colored per class, GT hit/miss markers) — overlays live as files for direct viewing rather than as report pages.

checkpointpositional · .pt or run dirrequired

Same resolution as evaluate.py: an explicit file, or a run directory (newest best_*). Architecture, classes, normalization, and thresholds all come from the checkpoint.

imagespositional · one or morerequired

Image files and/or directories (scanned for png/jpg/jpeg/bmp/tif/tiff — top level only unless --recursive). Loaded whole with Pillow and converted to RGB (or grayscale with --grayscale).

--recursive / -rflagdefault: off

Scan the given directories recursively, picking up images in every subdirectory. Because ground-truth matching and overlay assets go by filename only (directory paths never matter), a warning lists any filename that appears in more than one place — those images would share a GT entry and an overlay file.

--window-width / --window-heightint · required

Sub-window size in source pixels. Each window is resized to the model's 224x224 input, so choose the size that makes a target fill the window the way training snippets did. Windows larger than the image are clamped to the image size.

--stride-x / --stride-yintstride-y default: = stride-x

Window step in pixels, row-major (left-to-right, then down). The final row/column is clamped inward so the right/bottom edges are always covered — nothing at the border goes unexamined; edge windows just overlap a little more. Smaller strides find off-grid targets at the cost of proportionally more windows (a stride of window/2 evaluates ~4x the non-overlapping count).

--gtpath (.json)default: none

Ground-truth JSON in the GeoLabelling export schema: an images[] array whose entries carry point labels with class_name and normalized pixel_x / pixel_y (absolute-pixel exports are auto-detected and normalized via original_width/height). Entries are matched to input images by filename (name/stem/basename, case-insensitive) since export paths come from the labelling machine.

Scoring: a point counts as HIT when an accepted window of the same class contains it; detections covering no same-class point count as false-positive windows. Points whose class the model doesn't know are flagged and excluded from the hit rate. Adds:

  • a cover verdict — GT hit rate at the stored operating point (box colored green / amber / red by rate), false positives per image, specificity at 95% window recall with its threshold beside the stored one, and failure-mode counts — plus a per-class table (GT points, hits, hit rate, windows classified, confusions, rejections, AUC)
  • an Operating point page: a score-separation histogram (windows on GT points vs background, log scale) with the stored threshold and the fixed-recall thresholds marked — the single chart that shows whether the operating point is too strict — followed (after the per-class ROC) by confusion matrices: a full-width window-level true-class vs final-call matrix at the stored threshold, then a 2x2 page of the same matrix at each fixed-recall threshold, so you can watch the hard_negative column drain into the diagonal as the threshold drops, separating threshold-fixable misses from threshold-invariant class confusion
  • gt_results.csv — one row per point: image, id, class, pixel position, hit, best covering-window score, known-class flag
  • hit/miss markers on the overlay PNGs in assets/ (green circle = hit, red = miss)
  • GT columns in the report summary (points hit, FP windows) and an overall hit rate
  • failure-mode grids: windows accepted as the wrong genuine class (cross-class confusions, most confident first) and GT-covering windows rejected to hard_negative — partitioned into one section per true class, nearest the operating threshold first, each snippet captioned true class / argmax / s on separate lines (a window covering points of two classes appears under each) — the two ways a labelled point gets missed, shown as actual snippets
  • a Ground-truth metrics page: specificity at 85 / 90 / 95 / 98% recall (over all windows; positive = window covers a known GT point, score = genuineness s, with the achieved threshold per row — directly comparable to the stored operating threshold) and per-class ROC curves (score = P(class), positive = window covers a point of the class)
  • top-N snippet grids per class (--top-n): the highest-P(class) windows across all images, green-bordered when accepted AND sitting on a GT point of that class; each snippet is numbered #k and its source filename listed in a matching single-column table below the grid, so the grid stays a dense row-major 5-wide layout however long the filenames are
  • should-have-caught grids per class: every window covering a GT point, captioned with its confidence rank among all windows classified toward that class (e.g. "rank 2/29"), green when it passed the threshold with the right class, red when missed — makes the miss mode (e.g. off-center windows) visible at a glance. Windows whose argmax was a different class are not in that pool; they follow it labelled "not in pool: argmax X" rather than with an out-of-range rank. Every snippet caption carries both P(class) and the genuineness score s, and each class page states its acceptance cutoff on s (the stored global threshold, or the class's own in per-class mode) — the borders triage the failure mode: green = right class and past the cutoff, yellow = right argmax class but rejected by the threshold (an operating-point miss), red = wrong class (a classifier miss, whether accepted or not). A page dominated by yellow says lower the threshold; dominated by red says fix the model or its data
  • a final Per image page closing the report: every input image with its window, detection, GT-hit and false-positive counts, with the FP mean and standard deviation in the intro line — the reference table lives at the end so the diagnostic pages come first (without --gt the summary table stays on the cover). Long filenames are never truncated: table cells wrap them onto extra lines, and the top-N grids reference source images by number, keeping every filename whole in the legend column
--top-nintdefault: 10

With --gt: how many windows each per-class top-N grid shows.

--grayscaleswitchdefault: off (RGB)

Convert images to grayscale before windowing (channel-repeated to 3 for the model) — for models trained on grayscale snippets.

--batch-sizeintdefault: 64

Windows per forward pass. Pure throughput knob — the whole batch of raw uint8 crops is shipped to the GPU in one pinned transfer and resized/normalized on-device, so larger batches amortize well; raise it until GPU memory objects (256+ is comfortable on 8GB cards at 224px).

--no-ampswitchdefault: off (AMP on for CUDA)

Disable mixed precision. AMP is on by default on CUDA (roughly 4x end-to-end throughput combined with the batched GPU preprocessing) and produces identical decisions in practice — scores differ from fp32 by ~1e-3, which only matters for a window sitting exactly at a threshold. Pass this for bit-faithful fp32 scoring.

--out-dirpathdefault: inference_<UTCstamp>/

Destination for detections.csv, the PDF, and the overlays. --no-report skips the PDF (the CSV is always written); --device / --no-progress behave as everywhere else.

Overlapping windows are reported raw — one box per accepted window, no merging — so a single object found by several windows shows several boxes. The CSV is the ground truth for post-processing; images with zero detections appear only in the summary table.

gui.py — optional PyQt5 front-end

python gui.py — a thin command builder and runner over the three CLIs, for anyone who prefers forms to flags. It never re-implements the pipeline: each tab (Train / Evaluate / Inference) assembles the exact python train.py … command — shown live in a command preview bar as you edit — then launches it as a subprocess and streams its console output into the log pane; Stop kills the run. PyQt5 is an optional dependency, exactly like optuna: without it, python gui.py prints the install hint (pip install PyQt5) and exits. --self-test DIR renders the window offscreen, asserts the commands each tab builds, and saves tab screenshots — the smoke suite runs it whenever PyQt5 is installed.

curate.py — snippet curation GUI (optional)

python curate.py DATA.h5 — browse a training file's snippets by class and split, inspect them (double-click for a large preview), and remove bad ones from training entirely. The left panel selects the split and a class (with live counts, including how many of each class are removed); the grid pages through thumbnails 200 at a time with full multi-select — Ctrl/Shift-click, a dragged rubber band, Ctrl+A or the "Select page" button, with a live "N selected" counter — and Del or the Remove/Restore buttons act on the whole selection at once. How removal is stored. Save never rewrites the (possibly multi-GB, contiguous) images dataset — it writes an optional removed boolean dataset into the h5 (created on first save; now part of h5_format.md). Purging permanently. tests/make_real_h5.py — real public datasets

python tests/make_real_h5.py DATASET OUT.h5 --hn-classes N [options] — downloads a public torchvision dataset (mnist / fashionmnist — 28x28 grayscale; cifar10 / cifar100 — 32x32 RGB; cached in --data-dir after the first download) and converts it to the project's h5 format. A random subset of the original classes becomes the hard_negative class: --hn-classes N picks N at random with --seed, or --hn-names Pullover,Coat names them explicitly; the rest become the genuine classes. The torchvision train split is carved into train/validate (stratified, --val-frac, default 0.15); the torchvision test split becomes the test split. --subset-per-class caps samples per original class for quick experiments. The more classes you assign to hard_negative (e.g. cifar100 with --hn-classes 80), the closer the file gets to this pipeline's heavy-imbalance regime. Files are written with a contiguous, uncompressed images dataset so every per-sample read is a direct offset into the file; files generated by earlier versions (gzip-compressed) stream slowly — rewrite them with optimize_h5.py, or simply regenerate.

h5 image dtypes & grayscale storage

The images dataset may use any of four dtypes; the pixel range each is expected to hold:

uint8 0 – 255 the classic choice; smallest on disk uint16 0 – 65535 16-bit integer imagery (loader divides by 65535) float16 0.0 – 1.0 already-scaled 16-bit radiometry float32 0.0 – 1.0 already-scaled floats — 4x the disk/IO of uint8

validate_h5 rejects any other dtype and rejects float files whose sampled values leave [0, 1] (a 0–255 float file fails loudly instead of training garbage). Every dtype reaches the model as float32 in [0, 1] — verified equivalent to the uint8 pipeline within quantization — so checkpoints transfer across storage dtypes of the same imagery, and sliding-window inference (which reads image files, not h5) is unaffected. Grayscale storage (C=1) works with every dtype and is expanded to three identical channels at the model input, halving-to- thirding disk cost when color carries no signal. The curate GUI and all report thumbnails display every dtype correctly, and optimize_h5.py preserves the source dtype, including through --resize. Prefer uint8 unless the data genuinely holds more than 8 bits of dynamic range — float32 quadruples disk and read bandwidth for nothing on 8-bit sources.

tests/make_geotiffs.py — georeferenced labelling targets

python tests/make_geotiffs.py [--out-dir DIR --count N --size S --filled-frac F --gt-out GT.json --rename DRAWN=CLASS --seed K] — generates GeoTIFFs (requires rasterio; not a core dependency) of noisy gray scenes; a --filled-frac fraction of them (default: all) is scattered with simple shapes — circle, square, triangle, ring (a natural hard-negative foil for the circle) — all drawn in one muted color family so geometry, not color, is the class signal, while the rest stay pure background, mimicking sparse survey scenes. EPSG:3857 georeferencing at a 0.01 m pixel with per-image origins on a grid; plain-PIL-readable, so inference.py opens them directly. A manifest.json records every drawn shape and position for cross-checking labels, and --gt-out writes a ready-made ground truth in the GeoLabelling export schema (every image gets an entry; empty images carry an empty labels list), with --rename ring=torus-style mappings to match a model's class names — skipping the manual labelling step entirely for scale tests. Intended loop: label in GeoLabeller (or --gt-out), build the h5, train, then run inference.py --gt over the same images.

optimize_h5.py — rewrite any h5 for fast loading

python optimize_h5.py in.h5 out.h5 [--resize 224] [--sort-split] [--drop-removed] [--compression none|gzip|lzf] — rewrites any h5 in the project layout (whatever wrote it) with a contiguous, uncompressed images dataset (the default): every per-sample read becomes a direct offset into the file — no chunk lookup, no decompression — and the OS page cache serves repeats. Measured ~240x faster random reads than a default-chunked gzip source, with byte-identical pixels and metadata. The output is validated and a before/after size + read-throughput comparison is printed. --compression gzip/lzf trades read speed for disk (written with per-image chunks so reads stay sane).

--resize N optionally resizes every image to NxN (batched through the GPU when available). Worthwhile when sources are larger than the target — the file shrinks and training/evaluation skip their resize op for files already at model size. When sources are smaller, pre-resizing inflates the data by the square of the scale factor (32px to 224px is 49x); the script warns before doing it — for small sources keep the native size and let training resize (--workers parallelizes it).

--sort-split groups the output rows by split (train | validate | test) so each split is one contiguous region. Random per-sample training reads never become sequential — the sampler reshuffles every epoch — but confining them to the compacted train region, and streaming the every-epoch validation pass sequentially, speeds up larger-than-RAM files sharply. Measured on a ~20 GB file (which does not fit in page cache): the cold validation pass went ~22x (15 s → 0.7 s) and shuffled training reads ~2.2x; on a file that fits in RAM the gain is small after the first epoch, since the cache erases layout. A stable sort preserves each split's internal order. Caveat: reordering renames every row index, so a checkpoint's miner state and curate.py's removed references no longer align with the output — sort before training a run, not partway through one. --drop-removed permanently purges the snippets curate.py flagged (the removed dataset) instead of carrying them over, filtering all aligned datasets together and writing no removed dataset; it composes with --sort-split and --resize.

Checkpoint filenames

The best and last checkpoints carry their role, epoch, headline metrics, and a UTC timestamp in the filename:

best_e0041_rec0.9211_spec1.0000_20260819T153042Z.pt last_e0051_rec0.8824_spec1.0000_20260819T153055Z.pt

Exactly one file per role is kept — each save writes the new file and prunes the previous one (including legacy fixed-name best.pt / last.pt from older runs, which remain loadable until then). Because names vary, --resume and evaluate.py / report.py accept a run directory and resolve the newest checkpoint of the right role (last for resume, best for evaluation) — or an explicit .pt path as before. Smart-mode snapshots are also metric-stamped (snapshots/cycle003_rec0.9520_spec1.0000.pt); the controller-internal cycle_best.pt / milestone.pt keep fixed names.

report_<UTCstamp>.pdf & report_assets/

Unless --no-report is set, every training run ends with a timestamped report_<UTCstamp>.pdf (see the report group under train.py for contents) and report_assets/ holding its charts and thumbnail grids as standalone PNGs. Reports accumulate — each generation is a new file, so a run resumed or re-reported keeps its history (assets are overwritten, but each PDF embeds its own copies). evaluate.py writes its own report into its eval directory, and python report.py <run_dir> <data.h5> regenerates one for any past run from its checkpoints and CSVs.

Smart-mode files

Alongside last.pt / best.pt, a smart run maintains cycle_best.pt (best epoch of the current cycle), milestone.pt (last checkpoint stable at its pressure level — the rewind target), and snapshots/ (top-K cycle checkpoints of the run). Checkpoints additionally store the full controller state, so --resume continues the controller mid-flight.

What a checkpoint contains

Both last.pt and best.pt store: model weights, optimizer and AMP-scaler state, epoch index, the full CLI config, the class list and hard-negative index, the --imagenet-norm flag, the operating threshold(s) — the global scalar plus, in per-class mode, the {class: threshold} map and the floor — that epoch's validation metrics, the best-so-far selection key, miner scores, and ramp progress. Everything needed to resume training or to run correct inference lives in the one file.

Recipes

Standard run on a real dataset

python train.py data.h5 --arch resnet18 --epochs 60 ^
    --target-recall 0.95 --imbalance-ratio 3.0 --amp ^
    --out-dir runs/exp1

Recall-first, then squeeze specificity (full ramp)

python train.py data.h5 --arch resnet34 --epochs 80 --amp ^
    --target-recall 0.95 ^
    --imbalance-ratio 4.0 --imbalance-ratio-start 1.0 ^
    --hn-alpha 0.1 --hn-alpha-end 1.0 --ramp-epochs 10 ^
    --patience 15 --out-dir runs/exp2

Starts balanced with hard negatives nearly ignored; each epoch that holds 0.95 recall steps alpha and volume up one notch of ten.

Offline machine

# connected box
python download_weights.py --out-dir pretrained
# offline box, after copying the folder
python train.py data.h5 --arch resnet50 ^
    --weights-path pretrained/resnet50.pth --amp --out-dir runs/exp3

Evaluate, then compare against validation

python evaluate.py runs/exp2/best.pt data.h5              # test split
python evaluate.py runs/exp2/best.pt data.h5 --split 1    # sanity check

Resume after an interruption

python train.py data.h5 --arch resnet34 --epochs 80 --amp ^
    --target-recall 0.95 --imbalance-ratio 4.0 --imbalance-ratio-start 1.0 ^
    --hn-alpha 0.1 --hn-alpha-end 1.0 --ramp-epochs 10 --patience 15 ^
    --out-dir runs/exp2 --resume runs/exp2/last.pt

Same flags, same out-dir, plus --resume — --epochs is the absolute total, and the CSV continues in place.
