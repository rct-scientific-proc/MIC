Section 0

Core concepts the flags refer to

Genuineness score and operating threshold. The model is a K-class softmax classifier whose last class is always hard_negative. Every decision hangs off a single per-sample score:

s = P(not hard_negative) = 1 − softmax(logits)[hard_negative] accept as genuine ⇔ s ≥ threshold class of an accepted sample = argmax over the non-HN classes

The threshold is not trained. After every epoch, the validation split is swept and the largest threshold whose macro recall still meets --target-recall is chosen — recall is monotone in the threshold, so the largest passing value is the one with maximum hard-negative specificity. That number is saved inside every checkpoint and reused verbatim by evaluate.py. A checkpoint without its threshold is half a model.

Aggregated recall (genuine classes). A genuine sample counts as recalled only if it is accepted (s ≥ t) and classified as its true class. Per-class recalls over the genuine classes present in the split are then combined by --recall-agg:

macro mean(r₁ … r_C) (1,1,1,1,0.1) → 0.82 harmonic C / Σ(1/r_c) — 0 if any r=0 (1,1,1,1,0.1) → 0.36 min worst single class (1,1,1,1,0.1) → 0.10

The arithmetic mean can hide one collapsed class behind several perfect ones; the harmonic mean (the default) is dominated by the worst classes, so a recall target forces every class to perform. Each per-class recall is monotone in the threshold, and so is every aggregate — the sweep logic is identical for all three.

Hard-negative specificity. The fraction of hard negatives rejected (s < t) at the operating threshold. This is the number the pipeline is ultimately trying to maximize, subject to the recall constraint.

Checkpoint selection key. "Best" is ranked by the tuple:

( target met?, specificity at threshold, macro recall )

Meeting the recall target dominates everything; among target-meeting epochs, higher specificity wins; while the target is still out of reach, macro recall is the tie-breaker so early progress is still captured.

Section 1

train.py

python train.py DATA.h5 [options] — trains, validates, logs, checkpoints. Writes last.pt, best.pt, and metrics.csv into the output directory.

Positional & output

h5positional · pathrequired

The dataset file in the h5_format.md layout. On startup the file is validated: all arrays share the first axis, image shape is (N, H, W, C) with C ∈ {1, 3}, the last class is hard_negative, split values are {0, 1, 2}, and the gt flag is checked for consistency with labels == hard_negative. Any violation aborts before training starts. Training reads split 0, validation split 1; split 2 is never touched by this script.

--out-dirpathdefault: runs/<timestamp>

Where checkpoints and metrics.csv land. Reusing a directory appends to its existing metrics.csv — intended for --resume into the same directory; for a fresh experiment give a fresh directory.

Model group

--archresnet18 | resnet34 | resnet50default: resnet18

Backbone size. All three take the same 3×224×224 input and get a fresh K-class linear head. resnet18/34 (11.7M / 21.8M params) are usually enough for snippet-scale imagery and train markedly faster; resnet50 (25.6M, bottleneck blocks) buys capacity when classes differ in fine texture rather than gross shape. The architecture is recorded in the checkpoint, so evaluate.py rebuilds the right one automatically.

--no-pretrainedswitchdefault: off (pretrained)

Train from random initialization instead of ImageNet weights. Default behavior (flag absent) loads ImageNet weights from --weights-path if given, else from torchvision's cache (TORCH_HOME), downloading when online.

Gotcha From random init with few batches per epoch, BatchNorm running statistics lag the batch statistics: for the first ~10–15 epochs validation metrics can look collapsed (recall stuck at chance) while train loss is near zero. It self-recovers. Pretrained weights start from sane ImageNet BN stats and largely avoid the transient — one more reason they are the default.
--weights-pathpath (.pth)default: none

Load ImageNet weights from an explicit file instead of the network/cache — the offline-machine workflow. Produce the file with download_weights.py on a connected box and copy it over. The state dict is loaded into the stock 1000-class model, then the head is replaced, so the file must be the unmodified torchvision ImageNet checkpoint for the chosen --arch (they are not interchangeable across arches). Takes precedence over the cache; ignored if --no-pretrained is set.

Training group

--epochsintdefault: 50

Upper bound on epochs; early stopping (--patience) usually ends the run first. With --resume this is the absolute epoch count, not additional epochs — resuming an 8-epoch run with --epochs 10 trains epochs 8 and 9.

--batch-sizeintdefault: 64

Used for both training and validation loaders. Images are 3×224×224 floats after the input pipeline, so memory scales as ~0.6 MB per sample before activations; drop this first if CUDA runs out of memory, or raise it with --amp on. Batch size also sets how many samples share one BatchNorm statistic — very small values (<16) make BN noisy on top of the class-mix noise inherent to imbalanced sampling.

--lrfloatdefault: 3e-4

AdamW learning rate, constant for the whole run (no scheduler). 3e-4 is a solid fine-tuning rate for pretrained backbones; from-scratch training (--no-pretrained) sometimes wants 1e-3. If the ramp is enabled and metrics oscillate when hard-negative pressure steps up, lowering the LR is the first knob to reach for.

--weight-decayfloatdefault: 1e-4

AdamW's decoupled weight decay — L2-style shrinkage applied directly to weights rather than through the gradient. Mild regularization; raise toward 1e-2 if the genuine classes are tiny and the model overfits them, lower it if underfitting a large dataset.

--seedintdefault: 0

Seeds Python, NumPy, and torch RNGs, and parameterizes the sampler: the epoch-e draw uses generator seed seed·100003 + e, so a given (seed, epoch) pair always selects and shuffles the same hard negatives — which is what makes --resume line up with the original schedule. cuDNN autotuning is left on, so GPU runs are reproducible in structure but not bit-exact.

--devicecuda | cpudefault: auto

Auto picks CUDA when available. Forcing cpu is occasionally useful to rule out GPU nondeterminism or to train while the GPU is busy. --amp is silently inert on CPU.

--workersintdefault: 0

DataLoader worker processes. The dataset opens its h5 handle lazily inside each worker (never pickling an open handle), so multiprocess loading is safe on Windows' spawn start method. Economics: each worker re-spawns per epoch on Windows, costing a few seconds — for small datasets 0 is genuinely faster; for datasets where decode/resize dominates, 2–8 workers keep the GPU fed. Rule of thumb: raise it only when GPU utilization is low and epoch time is dominated by loading.

--ampswitchdefault: off

Mixed-precision training (CUDA only): forward/loss under autocast in fp16/bf16 with a gradient scaler guarding against underflow. Typically 1.5–2× faster and ~40% less memory on resnet50-class models with no accuracy cost. Validation always computes probabilities in fp32 after the logits, so threshold sweeps are unaffected. The scaler state is checkpointed and restored on resume.

--patienceintdefault: 10 · 0 = off

Early stopping: end the run after N consecutive epochs without improving the selection key (target met, specificity, macro recall) — see Core concepts. Because the key is exactly the training objective, "no improvement" means no better operating point, not merely no lower loss. Set 0 to always run the full --epochs.

Interaction With --ramp-epochs, specificity often dips right after each pressure step and recovers a few epochs later. Give patience enough headroom to ride the ramp out — patience < ramp recovery time can stop the run mid-ramp.
--resumepath (.pt)default: none

Continue from a checkpoint (normally last.pt). Restores model weights, optimizer state, AMP scaler, the epoch counter, the best-so-far selection key, the hard-negative miner's error scores, and ramp progress — the run picks up as if uninterrupted. Point --out-dir at the same directory to keep one continuous metrics.csv. Hyperparameters are not read back from the checkpoint: pass the same flags again (or deliberately different ones — resuming with a changed LR is allowed).

Objective group

--target-recallfloat 0–1default: 0.95

The recall constraint the validation threshold sweep must satisfy, in the aggregate chosen by --recall-agg. Semantics, precisely: after each epoch, candidate thresholds are every distinct score value in the validation split; the sweep keeps the largest one whose aggregated recall over genuine classes is ≥ this target, then reports hard-negative specificity at that threshold. If no threshold achieves the target, the epoch records target_met = 0 with threshold 0 (accept everything) and the achievable ceiling is logged as max_recall.

  • It does not change the loss — it defines the operating point and the checkpoint ranking.
  • It gates the pressure ramp: ramp progress only advances on epochs where the target was met.
  • Raising it trades specificity away one-for-one along the ROC curve; 0.99 on a 6-class problem is a much harder constraint than 0.95 because every class must clear it on average.
--recall-aggmacro | harmonic | mindefault: harmonic

How per-class recalls combine into the single number the target, the sweep, checkpoint selection, and the ramp gate all use (see Core concepts). Motivating failure case: five genuine classes at recalls (1, 1, 1, 1, 0.1) — macro reports 0.82 and can clear a 0.8 target while the fifth class is nearly dead; harmonic reports 0.36 and correctly fails, forcing the sweep to a threshold (and training toward a model) that serves every class. Guidance:

  • harmonic (default) — punishes weak classes progressively; any class at exactly 0 recall pins the aggregate to 0.
  • macro — the plain average; only appropriate when classes are interchangeable and a weak one is acceptable.
  • min — the strictest reading ("target means every class"); noisy when validation classes are small (one sample flips recall by 1/n).

The chosen aggregate is stored in checkpoints and in the recall_agg CSV column; evaluate.py reuses it so training and evaluation always report the same statistic.

--imbalance-ratiofloat ≥ 1, inf okdefault: inf

Caps how many hard negatives the model sees per epoch, relative to the genuine population:

hn_budget = min( n_hard_negatives, round(ratio × n_genuine) )

All genuine samples appear every epoch; only the hard negatives are subsampled. 1.0 means a balanced epoch (as many hard negatives as genuine samples); inf (the default) disables the cap and every hard negative is seen every epoch. When the cap binds, which hard negatives are drawn is decided by the miner (below) — so this flag is also the switch that makes mining matter at all: with an infinite ratio the miner has nothing to choose.

--focal-gammafloatdefault: 2.0

The focusing exponent in the focal loss:

FL(p_y) = −alpha[y] · (1 − p_y)^gamma · log(p_y)

γ = 0 recovers plain (alpha-weighted) cross-entropy; γ = 2 (the paper's default) down-weights already-confident samples by (1−p)² so the gradient concentrates on hard, misclassified examples — exactly the regime of a heavily imbalanced set where easy hard-negatives would otherwise drown the signal. Higher γ (3–5) focuses harder but can destabilize early training when everything is misclassified.

--hn-alphafloatdefault: 0.25

The focal alpha weight of the hard_negative class; every genuine class has alpha 1. At 0.25, a hard-negative's loss contribution is quartered: the model is punished lightly for accepting hard negatives and fully for missing genuine samples — the recall-first stance of early training. Raise it toward 1.0 (directly, or via the ramp) to increase the cost of false accepts once recall is established. Values above 1 are legal and flip the emphasis entirely toward specificity.

Hard-negative pressure ramp

One coordinated schedule for "start recall-focused, then turn up the pressure". Both endpoints interpolate linearly over --ramp-epochs steps, and progress advances only on epochs whose validation met the recall target — the ramp holds position whenever recall slips below target, so pressure never outruns the constraint.

--ramp-epochsintdefault: 0 (no ramp)

Number of ramp steps between the start and end values. 0 disables the schedule: --hn-alpha and --imbalance-ratio apply as-is from epoch 0 (end-values, with no interpolation). Note the unit is successful epochs, not epochs: a run that meets the target every epoch finishes the ramp in exactly this many epochs; a struggling run takes longer. Ramp position is checkpointed and restored by --resume.

--hn-alpha-endfloatdefault: = --hn-alpha

The hard-negative alpha at full ramp. At progress step k of N:

alpha(k) = hn_alpha + (k / N) · (hn_alpha_end − hn_alpha)

Typical use: --hn-alpha 0.1 --hn-alpha-end 1.0 — nearly ignore hard negatives until recall is secured, then weight them as full citizens. Leaving it unset keeps alpha constant while the ratio still ramps.

--imbalance-ratio-startfloat ≥ 1default: = --imbalance-ratio

The imbalance ratio at ramp step 0, interpolating toward --imbalance-ratio at full ramp. Set it low (e.g. 1.0) to begin with balanced epochs and let hard-negative volume grow only as recall holds. An infinite endpoint is handled in budget space: inf is treated as "the ratio that admits every hard negative", so the per-epoch hard-negative count still grows smoothly instead of jumping to everything at the final step.

Hard-negative mining

When the imbalance cap forces subsampling, mining decides which hard negatives fill the budget. Each hard negative carries an EMA of its focal loss (score ← 0.7·score + 0.3·loss, first observation taken directly); unseen samples start at a high sentinel score so everything gets tried before anything is written off. High-score (poorly handled) hard negatives are drawn preferentially via weighted sampling without replacement. Scores persist in checkpoints.

--no-miningswitchdefault: off (mining on)

Disable error-driven selection; the budget is filled uniformly at random each epoch. Useful as an ablation baseline, or when hard-negative losses are so uniform that mining adds nothing. Irrelevant when --imbalance-ratio inf (nothing is subsampled).

--mining-random-fracfloat 0–1default: 0.2

The exploration knob: this share of the hard-negative budget is drawn uniformly from the not-yet-mined remainder, the rest by error score. Without it, a hard negative scored low early (perhaps under a stale model) might never be revisited even though the current model would now fail on it — scores only update when a sample is actually seen. 0 is pure exploitation (risk of stale scores), 1 is equivalent to --no-mining. 0.2 keeps roughly one in five slots refreshing the score pool every epoch.

Data group

--imagenet-normswitchdefault: off

Input pipeline, always: uint8 HWC → CHW tensor → bilinear resize to 224×224 (antialiased) → scale to [0,1]; grayscale is repeated to 3 channels. With this flag, ImageNet channel statistics (mean 0.485/0.456/0.406, std 0.229/0.224/0.225) are additionally applied — matching what the pretrained backbone saw during ImageNet training, which can help transfer. Off by default per project convention (plain [0,1] inputs).

The flag is recorded in the checkpoint and evaluate.py replays it automatically — train/eval preprocessing can never silently diverge.
Section 2

evaluate.py

python evaluate.py CHECKPOINT.pt DATA.h5 [options] — runs a frozen checkpoint on a split using the checkpoint's stored threshold. It never re-tunes the operating point, which is what keeps a test evaluation honest: the threshold was chosen on validation, the test split only ever sees it applied.

checkpointpositional · pathrequired

best.pt or last.pt from a training run. The checkpoint supplies the architecture, class list, normalization flag, and threshold — you cannot pass a mismatched --arch by accident because there is no such flag here. The class list is cross-checked against the dataset and a mismatch aborts.

h5positional · pathrequired

The dataset to evaluate on — normally the same file used for training, but any file with an identical class list works (e.g. a newly collected test set exported with the same classes).

--split0 | 1 | 2default: 2 (test)

Which split to score: 0 train, 1 validate, 2 test. Evaluating split 1 should closely reproduce the training log's numbers for that epoch (a useful sanity check); split 0 measures memorization more than generalization.

--batch-sizeintdefault: 64

Inference batch size. Pure throughput knob — no gradients are stored, so this can usually be several times the training batch size.

--devicecuda | cpudefault: auto

Same semantics as training. CPU evaluation is fine for moderate test sets.

--workersintdefault: 0

DataLoader workers; same Windows economics as in training. A single pass rarely needs more than 0–2.

--out-dirpathdefault: <ckpt dir>/eval_<split>

Destination for report.txt, confusion.csv / confusion.png, roc_genuine_vs_hn.png (operating point marked), roc_per_class.png, calibration.png, and history.png. With more than 8 genuine classes the per-class ROC keeps the worst-AUC classes and the report lists which were omitted — nothing is dropped silently.

calibration.png is a reliability diagram of the genuineness score: samples are binned by predicted s, and each bin's observed genuine fraction is plotted against its mean prediction — the diagonal is perfect calibration, with the stored threshold marked and per-bin counts below. The report adds the expected calibration error (ECE), the count-weighted mean |observed − predicted|. A well-calibrated score makes the threshold interpretable as a probability; an overconfident one still ranks correctly (fine for ROC/threshold purposes) but its value shouldn't be read as P(genuine).

--history-csvpathdefault: metrics.csv beside the checkpoint

Source for the metric-vs-epoch plot. The default finds the training log automatically when the checkpoint still sits in its run directory; pass this explicitly if the checkpoint was copied elsewhere. Missing file ⇒ the history plot is skipped and noted in the report, everything else still runs.

Section 3

download_weights.py

python download_weights.py [options] — pre-fetches the ImageNet .pth files on a connected machine so offline boxes can train by copying a folder. Files already present are skipped, so re-running is cheap.

--out-dirpathdefault: pretrained

Destination folder; created if missing. Copy this folder to the offline machine and point train.py --weights-path at <folder>/<arch>.pth.

--archslistdefault: all three

Subset of resnet18 resnet34 resnet50 to fetch (≈45 / 84 / 98 MB). The URLs are the exact weight versions model.py loads (IMAGENET1K_V1 for 18/34, IMAGENET1K_V2 for 50), so a file fetched here is guaranteed to match what --weights-path expects.

Section 4

tests/make_synthetic_h5.py

python tests/make_synthetic_h5.py OUT.h5 [options] — generates a small learnable dataset in the exact h5_format.md layout. Genuine classes are brightness bands; hard negatives sit halfway between two neighboring bands, so they genuinely "look like" a class. Doubles as a worked example of the format.

outpositional · pathrequired

Output .h5 path (overwritten if present).

--num-classesintdefault: 2

Number of genuine classes (band0…bandN); hard_negative is always appended as the last class. More classes squeeze the brightness bands closer together, making the problem harder.

--genuine-per-classintdefault: 30

Genuine training samples per class. Validation and test each get one third of this (minimum 2) per class.

--hn-factorfloatdefault: 5.0

Hard negatives per genuine sample, per split — the dataset's imbalance severity. At the default, each split is 5:1 hard-negative-heavy, enough for --imbalance-ratio caps and mining to actually engage.

--sizeintdefault: 28

Image height and width. Kept small on purpose — the input pipeline resizes to 224 anyway, and small sources keep the file and the test fast.

--channels1 | 3default: 1

Grayscale or RGB source images — use 1 to exercise the grayscale→RGB repeat path in the dataset.

--seedintdefault: 0

RNG seed for band noise and hard-negative placement; same seed, same file.

Outputs: metrics.csv & checkpoint contents

metrics.csv columns

columnmeaning
epoch0-based epoch index
train_lossmean per-sample focal loss over the epoch's draw
thresholdoperating threshold chosen by this epoch's validation sweep
target_met1 if some threshold reached --target-recall, else 0
recallaggregated recall over genuine classes at the chosen threshold
recall_aggthe aggregate in effect (macro / harmonic / min)
specificityfraction of validation hard negatives rejected at the threshold
max_recallrecall ceiling with everything accepted (threshold → 0)
aurocgenuine-vs-hard-negative AUROC of the score s
hn_alphafocal alpha of the HN class in effect this epoch (ramp-aware)
imbalance_ratioratio in effect this epoch (ramp-aware)
ramp_progressramp steps completed (0…--ramp-epochs)
lrlearning rate (constant)
epoch_time_swall-clock seconds for train + validate

What a checkpoint contains

Both last.pt and best.pt store: model weights, optimizer and AMP-scaler state, epoch index, the full CLI config, the class list and hard-negative index, the --imagenet-norm flag, the operating threshold, that epoch's validation metrics, the best-so-far selection key, miner scores, and ramp progress. Everything needed to resume training or to run correct inference lives in the one file.

Section 6

Recipes

Standard run on a real dataset

python train.py data.h5 --arch resnet18 --epochs 60 ^
    --target-recall 0.95 --imbalance-ratio 3.0 --amp ^
    --out-dir runs/exp1

Recall-first, then squeeze specificity (full ramp)

python train.py data.h5 --arch resnet34 --epochs 80 --amp ^
    --target-recall 0.95 ^
    --imbalance-ratio 4.0 --imbalance-ratio-start 1.0 ^
    --hn-alpha 0.1 --hn-alpha-end 1.0 --ramp-epochs 10 ^
    --patience 15 --out-dir runs/exp2

Starts balanced with hard negatives nearly ignored; each epoch that holds 0.95 recall steps alpha and volume up one notch of ten.

Offline machine

# connected box
python download_weights.py --out-dir pretrained
# offline box, after copying the folder
python train.py data.h5 --arch resnet50 ^
    --weights-path pretrained/resnet50.pth --amp --out-dir runs/exp3

Evaluate, then compare against validation

python evaluate.py runs/exp2/best.pt data.h5              # test split
python evaluate.py runs/exp2/best.pt data.h5 --split 1    # sanity check

Resume after an interruption

python train.py data.h5 --arch resnet34 --epochs 80 --amp ^
    --target-recall 0.95 --imbalance-ratio 4.0 --imbalance-ratio-start 1.0 ^
    --hn-alpha 0.1 --hn-alpha-end 1.0 --ramp-epochs 10 --patience 15 ^
    --out-dir runs/exp2 --resume runs/exp2/last.pt

Same flags, same out-dir, plus --resume — --epochs is the absolute total, and the CSV continues in place.
